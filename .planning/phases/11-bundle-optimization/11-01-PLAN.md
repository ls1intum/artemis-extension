Modify esbuild.js to add bundle size console reporting and improve metafile generation:

1. Add a `formatSize` helper function at the top (after the imports/constants):
```javascript
const formatSize = (bytes) => {
  const kb = bytes / 1024;
  const mb = kb / 1024;
  return mb >= 1 ? `${mb.toFixed(2)} MB` : `${kb.toFixed(2)} KB`;
};
```

2. Enable `metafile: true` on the extension host context (line ~34) — currently only the webview has it.

3. In the non-watch build path (the `else` block starting ~line 85), after both rebuilds complete:

   a. Write BOTH metafiles (rename from `meta.json` to `meta-webview.json` and `meta-extension.json`):
   ```javascript
   // Write metafiles for bundle analysis
   if (webviewResult.metafile) {
     await fs.promises.writeFile(
       path.join(__dirname, 'dist/meta-webview.json'),
       JSON.stringify(webviewResult.metafile)
     );
   }
   if (extensionResult.metafile) {
     await fs.promises.writeFile(
       path.join(__dirname, 'dist/meta-extension.json'),
       JSON.stringify(extensionResult.metafile)
     );
   }
   ```
   Note: The extension rebuild call needs to capture its result (`const extensionResult = await extensionCtx.rebuild();`).

   b. Add size reporting ALWAYS (not just production):
   ```javascript
   const extStats = fs.statSync(path.join(__dirname, 'dist/extension.js'));
   const webviewStats = fs.statSync(path.join(__dirname, 'dist/webview-react.js'));
   console.log(`[build] extension.js: ${formatSize(extStats.size)}`);
   console.log(`[build] webview-react.js: ${formatSize(webviewStats.size)}`);
   console.log(`[build] Total: ${formatSize(extStats.size + webviewStats.size)}`);
   ```

4. Remove the old `if (production && webviewResult.metafile)` block that writes `dist/meta.json` — replaced by the dual metafile approach. Metafiles are always written (not just production) so developers can analyze dev builds too.

Important: Keep all existing plugins, loaders, and configuration unchanged. Only add the metafile flag to extension context, change the rebuild flow to capture both results, and add the reporting/metafile-write logic.

Three changes across three files:

**eslint.config.mjs — Add no-restricted-imports rule for Lucide:**

Add to the main rules object (second config block, the one with `@typescript-eslint` rules):
```javascript
'no-restricted-imports': ['error', {
    patterns: [{
        group: ['lucide-react'],
        importNamePattern: '^\\*$',
        message: 'Do not use wildcard imports from lucide-react. Use named imports: import { IconName } from "lucide-react".',
    }],
}],
```

This catches `import * as Icons from 'lucide-react'` but allows `import { Check, X } from 'lucide-react'` (which is the correct tree-shakeable pattern already used in the codebase).

Note: Do NOT use a blanket restriction on the group that blocks all imports — only block wildcard/namespace imports. Named imports like `import { Check } from 'lucide-react'` are correct and must remain allowed.
