**Step 1: Install and run automated analysis tools (temporary, not committed to package.json)**

Run dependency analysis using npx (no permanent install needed):

```bash
cd iris-thaumantias
# Circular dependency detection
npx madge --circular --extensions ts,tsx src/ 2>&1

# Full dependency graph stats
npx madge --extensions ts,tsx src/ --json 2>&1 | head -200

# Orphan module detection
npx madge --orphans --extensions ts,tsx src/ 2>&1
```

If madge fails due to TypeScript config issues, fall back to manual grep-based analysis:
```bash
# Find circular import patterns
grep -r "from '\.\." src/ --include="*.ts" --include="*.tsx" | sort
# Count imports per module
for f in src/**/*.ts src/**/*.tsx; do echo "$(grep -c "^import" "$f") $f"; done | sort -rn | head -30
```

Capture all output for inclusion in raw findings.

**Step 2: Systematic structural review of all five areas**

Review EVERY source file. For each area below, read the relevant files and document observations.

**Area 1 - Component Structure:**
- Read all files in `src/views/webview/react/` — evaluate component hierarchy, naming, prop patterns
- Read all files in `src/views/webview/react/components/` — evaluate shared component design
- Read all files in `src/views/webview/react/views/` — evaluate view component patterns
- Read all files in `src/views/webview/react/stores/` — evaluate store composition
- Read legacy view files in `src/views/` (dashboard, courseList, etc.) — identify dead code from migration
- Check `src/views/components/` — identify pre-React components that may be dead code
- Assess: hierarchy depth, naming consistency, prop drilling vs store usage, component size distribution

**Area 2 - State Management:**
- Read all 9 Zustand stores in `src/views/webview/react/stores/`
- Read `src/views/app/appStateManager.ts` — assess legacy state management
- Read `src/services/contextStore.ts` — assess context persistence
- Assess: store boundaries (god-stores vs fragmentation?), selector patterns, middleware usage, state persistence approach, dual state management (Zustand + AppStateManager coexistence)

**Area 3 - Message Contracts:**
- Read message types/contracts — find all postMessage patterns between extension and webview
- Read `src/views/app/webViewMessageHandler.ts` — assess message routing
- Read `src/views/app/commands/*.ts` — assess command handler patterns
- Read `src/views/webview/react/hooks/` (if exists) or message handling in React components
- Assess: type safety of contracts, exhaustive case handling, runtime validation, dual format support (typed + legacy)

**Area 4 - Build Pipeline (light touch per CONTEXT.md):**
- Read `esbuild.js` — note any glaring issues only
- Read `package.json` scripts section — note build/test scripts
- Read `tsconfig.json` — note compiler settings
- Note: Phase 11 handles bundle optimization in depth. Only flag obvious problems.

**Area 5 - WebSocket Handling:**
- Read `src/services/artemisWebsocketService.ts` — assess connection lifecycle, error propagation, subscription cleanup
- Read `src/services/websocketStatusBar.ts` — assess status UI
- Read WebSocket-related handlers in providers — assess event routing
- Assess: error propagation to UI, subscription cleanup, reconnection robustness, state machine clarity

**Additional areas per CONTEXT.md locked decisions:**
