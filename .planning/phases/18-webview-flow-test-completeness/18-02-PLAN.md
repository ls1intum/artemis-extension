describe('{messageType} hydrates {ViewName} local state', () => {

**CRITICAL PITFALLS:**
1. ALWAYS `render(<View vscodeApi={mockApi} />)` BEFORE `dispatchExtensionMessage()` — the view's `useEffect` registers the window message listener on mount. Without rendering first, the message fires into the void.
2. ALWAYS wrap dispatch in `await act(async () => { ... })` — Zustand setState triggers React re-renders that need to be flushed.
3. IrisChat uses `updateIrisState` (not `*Init`). The handler is in IrisChatView and calls `useChatStore.setIrisState()` or similar. Check the actual handler.
4. LoginView uses `showLoggedIn` (not `loginInit`). Check the actual handler.
5. For views 1-4, read each view's message handler to understand what DOM elements are rendered from the init data.
6. Each `describe` block should contain exactly 1 test (`it`).
