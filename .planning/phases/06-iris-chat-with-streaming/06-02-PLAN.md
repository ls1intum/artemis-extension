**1. CodeBlock component (`CodeBlock.tsx` + `.module.css`):**

Shiki-powered syntax highlighting with language label and copy button:
- Accept `language` (string) and `code` (string, children) props
- Use Shiki's `codeToHtml()` for highlighting. Initialize highlighter lazily with `createHighlighter()` — use a module-level singleton Promise to avoid re-creating on each render.
- Languages to bundle: java, python, c, javascript, typescript, sql, shellscript (per user decision: "basic/common language set")
- Theme: Use a VS Code-compatible theme (e.g., `github-dark` for dark, `github-light` for light). Since we're in a VS Code webview, use `css-variables` theme option if Shiki supports it — otherwise pick one dark theme and let VS Code CSS variables handle the rest.
- Header bar with language label (left) and copy button (right, small clipboard icon)
- Copy button: On click, use `navigator.clipboard.writeText(code)` and show brief "Copied!" feedback (change button text for 2s then revert)
- No line numbers per user decision
- CSS: `var(--vscode-editor-background)` for code block background, `var(--vscode-editor-foreground)` for text, rounded corners, horizontal scroll for overflow
- During streaming (when code is still arriving), show unhighlighted code with a CSS class — apply highlighting on a debounced basis (300ms debounce) OR simply re-highlight on every chunk if the code is short. For very long streaming code blocks, consider falling back to unhighlighted display until streaming finishes.

**2. StreamingMessage component (`StreamingMessage.tsx` + `.module.css`):**

Progressive markdown rendering via Streamdown:
- Accept `chunks` (string[]) prop from the streaming state
- Join chunks into single content string
- Render via `<Streamdown>` component (from `streamdown` package)
- Override the `code` component slot to render `<CodeBlock>` for fenced code blocks
- Each new chunk wraps in a span with `.messageChunk` CSS class for fade-in animation
- CSS fade-in: `opacity: 0; animation: fadeIn 150ms ease-in forwards;` (per user decision: ~150ms)

**IMPORTANT about Streamdown API:** Read the actual streamdown package exports before implementing. It may export as `<Streamdown>` component or as a hook. The RESEARCH.md shows `import Streamdown from 'streamdown'` — verify this is the correct import. Streamdown is a react-markdown replacement, so it likely accepts children as markdown string and `components` prop for overrides.

If Streamdown turns out to be incompatible or its API differs significantly, fall back to `react-markdown` with a custom streaming wrapper that handles incomplete syntax (close open backtick sequences, close bold markers, etc. before passing to parser).

- Iris icon next to assistant messages only (use inline SVG iris logo or a simple bot icon). No avatar for user messages.
- Timestamp shown on hover (relative time, e.g., "2 min ago") — use a simple helper function or the existing `useRelativeTime` hook pattern
- Feedback buttons (thumbs up/down): appear on hover over assistant messages only. Use inline SVG icons.

  - Call `onFeedback` callback on click
  - Apply `has-feedback` class to keep buttons visible when one is selected
- For streaming messages (`isStreaming=true`): render `<StreamingMessage chunks={streamingChunks} />` instead of static content
- For completed messages: render content as markdown via `<Streamdown>` (same component rendering as StreamingMessage but with final content)
- Optimistic error state: if `message.status === 'error'`, show error styling with `message.errorMessage` and a retry option

**React.memo custom comparator:**

```typescript
(prev, next) => {

           prev.message.status === next.message.status &&
           prev.isStreaming === next.isStreaming &&
           prev.streamingChunks?.length === next.streamingChunks?.length;
}
```
