    **repositoryCommands.ts (93 errors):**
    - Git/repository-related data types — may need small interfaces for clone status, repo info
    - Exercise data → use ExerciseDetail or ExerciseDetailsResponse from apiResponses
    - Build error data → type with interface matching actual shape
    - Repository status messages → use typed messages from Plan 12-04

    **utilityCommands.ts (91 errors):**
    - Utility/developer commands with varied data shapes
    - Settings/config data → create minimal typed interfaces or use Record<string, unknown>
    - Notification data → type with notification message types
    - `catch (error: any)` → standard unknown pattern

    **Key typing strategies:**
    1. **Message parameters:** Use discriminated union narrowing from messageContracts.ts. Access payload only after checking message.type/command.
    2. **API response data:** Import domain types from apiResponses.ts. If the API returns additional fields not in the interface, add `[key: string]: unknown` index signature.
    3. **Intermediate variables:** If a variable holds API data, type it explicitly: `const courses: CourseDashboardResponse = await fetchCourses();`
    4. **Catch blocks:** ALWAYS `catch (error: unknown)`. Use helper: `const message = error instanceof Error ? error.message : String(error);`
    5. **Callback parameters:** Add explicit types to .map, .filter, .find callbacks
    6. **Type assertions:** Allowed minimally with comment. Prefer type guards when possible.
