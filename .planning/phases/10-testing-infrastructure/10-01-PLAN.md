    **Step 1: Create vscodeApi.ts** in `test/react/__helpers__/vscodeApi.ts`:

    Import `vi` from `vitest` and `VsCodeApi` type from `../../../src/shared/messageContracts`.

    Export `createMockVsCodeApi(overrides?: Partial<VsCodeApi>): VsCodeApi`:
    - Returns object with:
      - `postMessage: vi.fn()`
      - `getState: vi.fn(() => undefined)`
      - `setState: vi.fn()`
      - Spread `...overrides` to allow per-test customization

    Export `dispatchExtensionMessage(message: Record<string, unknown>): void`:
    - Creates a `new MessageEvent('message', { data: message })`
    - Dispatches on `window` via `window.dispatchEvent(messageEvent)`
    - Use `Record<string, unknown>` for the message type since we need flexibility for both typed and legacy message formats

    Export `getPostMessageCalls(vscodeApi: VsCodeApi)`:
    - Convenience accessor: `return (vscodeApi.postMessage as ReturnType<typeof vi.fn>).mock.calls`
    - Makes it easier to inspect message payloads in tests

    **Step 2: Create renderWithProviders.tsx** in `test/react/__helpers__/renderWithProviders.tsx`:

    Import `render` and `RenderOptions` from `@testing-library/react`.
    Import `ReactElement` from `react`.
    Import `VsCodeApi` from `../../../src/shared/messageContracts`.
    Import `createMockVsCodeApi` from `./vscodeApi`.

    Define `CustomRenderOptions` extending `Omit<RenderOptions, 'wrapper'>`:
    - `vscodeApi?: VsCodeApi` — custom VS Code API mock (defaults to createMockVsCodeApi())

    Export `renderWithProviders(ui: ReactElement, options?: CustomRenderOptions)`:
    - Destructure `vscodeApi = createMockVsCodeApi()` and `...renderOptions` from options
    - Call `render(ui, renderOptions)`
    - Return `{ ...renderResult, vscodeApi }`

    Re-export everything from `@testing-library/react`:
    ```typescript
    export * from '@testing-library/react';
    ```

    Also re-export `userEvent` from `@testing-library/user-event`:
    ```typescript
    export { default as userEvent } from '@testing-library/user-event';
    ```

    **Note on Zustand store setup:** Zustand stores are module-scoped singletons that don't need React Context providers. Store state resets happen via `store.setState()` in `beforeEach` blocks, not via wrapper components. The `renderWithProviders` helper focuses on VS Code API injection. If future phases need more complex provider wrapping, it can be extended.
