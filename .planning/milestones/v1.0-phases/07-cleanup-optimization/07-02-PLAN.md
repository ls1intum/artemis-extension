  <action>
    **Step 1: Remove the legacy webview-components build context** from esbuild.js:
    - Delete the entire `webviewCtx` block (the second esbuild.context that builds `src/views/webview/components.ts` into `dist/webview-components.js`).
    - Remove `webviewCtx.watch()`, `webviewCtx.rebuild()`, `webviewCtx.dispose()` calls.
    - This file was deleted in Plan 01 Task 1, so the build would fail anyway.

    **Step 2: Remove the copyCssPlugin** from esbuild.js:
    - Delete the entire `copyCssPlugin` object (lines ~33-81 that copy CSS from src/views to dist/views and copy base.css).
    - Remove `copyCssPlugin` from the extension build's plugins array.
    - Legacy CSS is no longer needed — React uses CSS Modules bundled into webview-react.css.

    **Step 3: Enable metafile generation** in the React webview build:
    - Add `metafile: true` to the webviewReactCtx configuration.
    - After the production build completes, write the metafile to `dist/meta.json`:
      ```javascript
      if (!watch && production) {
          const result = await webviewReactCtx.rebuild();
          await require('fs').promises.writeFile(
              'dist/meta.json',
              JSON.stringify(result.metafile)
          );
      }
      ```
    - Note: In non-production/watch mode, continue using the existing rebuild pattern.

    **Step 4: Enable source maps in production builds:**
    - Change `sourcemap: !production` to `sourcemap: true` for BOTH the extension and React webview contexts.
    - This ensures source maps are always generated (user decision: "Source maps included in production builds").
    - Keep `sourcesContent: false` to avoid bloating source maps.

    **Step 5: Add `npm run analyze` and `npm run build:analyze` scripts** to package.json:
    ```json
    "analyze": "npx esbuild-visualizer --metadata=dist/meta.json --open",
    "build:analyze": "npm run package && npm run analyze"
    ```
    - `npm run analyze` opens interactive bundle visualization from existing metafile.
    - `npm run build:analyze` does a production build first, then opens the visualizer.

    **Step 6: Add coordinated `npm run dev` script** to package.json:
    ```json
    "dev": "node esbuild.js --watch"
    ```
    - Since esbuild.js already supports --watch mode and watches both extension + webview-react contexts concurrently, this single command handles both build targets.
    - User decision: "Coordinated watch mode: single `npm run dev` watches both extension host and webview."

    **Step 7: Verify the two remaining build contexts are correct:**
    - extensionCtx: `src/extension.ts` → `dist/extension.js` (CJS, Node.js)
    - webviewReactCtx: `src/views/webview/react/index.tsx` → `dist/webview-react.js` (IIFE, browser)
    - No other build contexts should remain.

    Commit message: `build(07): optimize esbuild config, add metafile analysis, remove legacy targets`
