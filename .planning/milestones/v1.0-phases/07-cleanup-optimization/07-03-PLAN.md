  <action>
    **Step 1: Read all 9 store files** to understand their current structure, state shape, and persistence configuration.

    **Step 2: Identify consolidation candidates.**
    Evaluate overlap between stores:
    - `useCourseListStore` + `useCourseDetailStore`: Both manage course-related data. Check if they share state fields (courses array, selected course, etc.). If > 50% state overlap, merge into a single `useCourseStore`. Per research recommendation: "Audit during planning, merge if > 50% state overlap."
    - `useExamStartStore` + `useExamConductionStore` + `useExamExerciseDetailStore`: All exam-related. Check if they share exam data. If they each manage independent view state with no overlap, keep separate.
    - `useDashboardStore`, `useChatStore`, `useNavigationStore`, `useExerciseDetailStore`: Likely independent — keep separate.

    **Decision rule for consolidation:**
    - Merge if stores share > 50% of state fields AND are used in related views
    - Keep separate if stores have independent lifecycle (e.g., chat store vs course store)
    - User decision: "Full audit and consolidation of Zustand stores — merge overlapping stores"
    - User decision: "Keep per-store persistence logic (no shared middleware)"

    **Step 3: Add DevTools middleware to ALL stores.**
    For each store, wrap the existing `create` call with `devtools`:

    ```typescript
    import { devtools } from 'zustand/middleware';

    export const useXxxStore = create<XxxStore>()(
        devtools(
            // existing store creator (with or without persist)
            (set, get) => ({
                // ... state and actions
            }),
            {
                name: 'XxxStore',  // Human-readable name in Redux DevTools
                enabled: process.env.NODE_ENV === 'development'  // Dev-only
            }
        )
    );
    ```

    If store already uses `persist`, nest: `devtools(persist(...), { name: 'XxxStore' })`
    The `devtools` middleware wraps the outermost layer.

    **Step 4: Enforce consistent naming conventions:**
    - File names: `useXxxStore.ts` (already consistent)
    - Export names: `useXxxStore` (already consistent)
    - DevTools label: `XxxStore` (without the `use` prefix)
    - Action names in `set()`: Use named actions for DevTools tracking: `set({ ... }, false, 'actionName')`
      - Example: `set({ filter }, false, 'setFilter')` instead of just `set({ filter })`
      - This enables Redux DevTools to show action names in the timeline

    **Step 5: Remove any leftover coexistence router state** from stores.
    - Search stores for references to legacy view names, migration flags, or coexistence patterns.
    - Clean up any state fields that were only relevant during the migration period.

    **Step 6: Verify all store consumers still work** after consolidation:
    - If stores were merged, update all import paths in consuming view components.
    - Run `npx tsc --noEmit` to verify.

    Commit message: `refactor(07): consolidate Zustand stores and add DevTools middleware`
