    **Fix 21 TS2353 errors + 2 TS2322 ("info" not assignable) + 1 TS2345 (ExerciseDetail vs ExerciseSource):**

    Extension host commands send messages using `{ command: 'foo', ...data }` legacy format. The typed `ExtensionToWebviewMessage` union doesn't include these legacy messages, causing 21 TS2353 errors ("'command' does not exist in type 'ExtensionToWebviewMessage'").

    **Strategy — Decision rule for approach selection:**

    **Step 1: Count unique command shapes.** Run:
    ```bash
    grep -rn "command:" src/views/app/commands/*.ts | grep -oP "command:\s*'[^']+'" | sort -u | wc -l
    ```

    **Step 2: Apply decision rule:**
    - **If <15 unique command shapes → Option A** (typed per-command interfaces)
    - **If >=15 unique command shapes → Option B** (LegacyCommandMessage escape hatch)
    - **Document the count and chosen option** in the SUMMARY.md after execution.

    **Option A: Add typed legacy command interfaces to ExtensionToWebviewMessage union.**
    Read each command file and catalog all unique `{ command: '...' }` message shapes. For each, create a typed message interface and add it to the ExtensionToWebviewMessage union in messageContracts.ts:
    ```typescript
    export interface RepositoryStatusMessage {
        command: 'repositoryStatus';
        payload: { status: string; repoPath: string };
    }
    // Add to ExtensionToWebviewMessage union
    ```
    This preserves the existing runtime message format while adding type safety.

    **Option B: Use LegacyCommandMessage escape hatch.**
    Add a single `LegacyCommandMessage` to the union:
    ```typescript
    export interface LegacyCommandMessage {
        command: string;
        [key: string]: unknown;
    }
    // Add to ExtensionToWebviewMessage union
    ```
    This is less type-safe but fixes compilation immediately. The individual command typing can continue in a follow-up plan.

    **Also fix:**
    - 2 TS2322 in repositoryCommands.ts: `"info"` literal not in `"success" | "error" | "warning"` union. Either add `"info"` to the notification level type in messageContracts.ts, or change `"info"` to `"warning"` if semantically appropriate.
    - 1 TS2345 in repositoryCommands.ts line 92: `ExerciseDetail` not assignable to `ExerciseSource`. Fix by extracting the required fields: `{ id: exercise.id!, ... }` or by aligning the types.
    - 2 TS2345 in navigationCommands.ts: `unknown` not assignable to `number`. Add type narrowing: `typeof value === 'number' ? value : 0`.

    **Verify after task:** `npx tsc --noEmit 2>&1 | grep "TS2353\|TS2322\|TS2345" | wc -l` should return 0 or only show webview-layer errors.
