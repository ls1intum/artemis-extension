  <action>
    In `ArtemisWebviewProvider.resolveWebviewView()`, add an `onDidChangeVisibility` listener following the same pattern as `ChatWebviewProvider` (line 206).

    **Add after the `webviewView.webview.onDidReceiveMessage()` block (around line 480):**

    ```typescript
    // Handle visibility changes — resend data when panel becomes visible
    const visibilityListener = webviewView.onDidChangeVisibility(() => {
        if (webviewView.visible) {
            logger.debug('Sidebar webview became visible, resending view data...', LogCategory.VIEW);
            this.resendViewData();
        } else {
            logger.debug('Sidebar webview became hidden', LogCategory.VIEW);
        }
    });
    this._extensionContext.subscriptions.push(visibilityListener);
    ```

    **Key constraints (from research, pitfall 3):**
    - With `retainContextWhenHidden: true`, the webview JS context stays alive across hide/show. The `ready` signal fires exactly ONCE per webview creation.
    - `_webviewReady` stays `true` across hide/show — do NOT reset it.
    - `_pendingMessages` is NOT used for hide/show — `_postMessageSafe()` posts directly because `_webviewReady` is already true.
    - The `onDidChangeVisibility` event fires on BOTH hide and show. ALWAYS check `webviewView.visible` before acting.
    - `resendViewData()` already handles `dashboard`, `course-list`, `course-detail`, `exercise-detail` states. Verify it also covers `login`, `service-status`, `recommended-extensions`, `exam-start`, `exam-conduction`, `exam-exercise` — if any are missing, add them as simple `_postMessageSafe()` calls sending the appropriate `*Init` message with current `_appStateManager` data. If a state has no meaningful data to resend (like `login` which just needs a server URL), add it.

    **Auth expiry handling:**
    The `_checkExistingAuthentication()` method already runs during initial `resolveWebviewView()`. For the visibility listener, add a lightweight auth check: if `this._authManager.isAuthenticated()` returns false but the current state is NOT `login`, call `this.hideLoadingAndSendServerUrl()` to transition to login. This handles the case where auth expired while the panel was hidden.

    Approximate addition to the visibility listener:
    ```typescript
    if (webviewView.visible) {
        // Check if auth expired while hidden
        const isAuthenticated = await this._authManager.isAuthenticated();
        const currentState = this._appStateManager.currentState;
        if (!isAuthenticated && currentState !== 'login') {
            logger.debug('Auth expired while panel was hidden, showing login', LogCategory.VIEW);
            this.hideLoadingAndSendServerUrl();
            return;
        }
        this.resendViewData();
    }
    ```
    Note: This makes the callback async. Wrap the body in `void (async () => { ... })()` to avoid unhandled promise rejection since `onDidChangeVisibility` expects `void`.
