<!-- Decision rules for what to remove vs. keep -->

REMOVE a `beforeEach` block (or the store.setState call within it) when:
- The entire body is `store.setState({ ...defaultValues })` where defaultValues match the store's initial state
- The block resets a store to its documented default: empty arrays, null values, false booleans, etc.
- Removing it makes the test depend solely on the global resetTestState()

KEEP a `beforeEach` setState call when:
- It sets up scenario-specific state (e.g., `isLoading: true`, specific course data, pre-populated messages)
- The values differ from the store's initial defaults
- Removing it would change the test's starting conditions

KEEP the entire `beforeEach` block when:
- It contains other setup logic beyond store resets (e.g., mock setup, component rendering, spy configuration)
- Only remove the redundant store.setState lines within it

If a `beforeEach` block becomes EMPTY after removing the redundant reset, remove the entire `beforeEach` block.
