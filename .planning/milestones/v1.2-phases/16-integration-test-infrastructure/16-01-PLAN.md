2. Import `createMockVsCodeApi` from `./vscodeApi`

   - Do NOT use `JSON.parse(JSON.stringify(...))` — this strips action functions from state
   - Do NOT use `structuredClone` — direct reference from `getState()` is safe because Zustand uses immutable updates

   - Iterates over the captured entries
   - Calls `store.setState(capturedState, true)` for each — the `true` (replace) flag overwrites entire state instead of merging
   - Cast the store's `setState` to accept `(state: unknown, replace: boolean)` to avoid TypeScript narrowing issues
   - Re-initializes `window.acquireVsCodeApi` with a fresh `createMockVsCodeApi()` via `Object.defineProperty` with `writable: true` and `configurable: true`

Create `simulateHandshake.ts` — Bridge handshake helper:

1. Import `act` from `@testing-library/react`
2. Import `dispatchExtensionMessage` from `./vscodeApi`
3. Import type `ExtensionToWebviewMessage` from `../../../src/shared/messageContracts`
4. Export async function `simulateHandshake(initPayload?: ExtensionToWebviewMessage): Promise<void>`
   - Wraps dispatch in `await act(async () => { ... })` so React processes state updates before control returns
   - If `initPayload` is provided, calls `dispatchExtensionMessage(initPayload as Record<string, unknown>)` inside the act block
   - If `initPayload` is undefined, the function is a no-op (used to test loading state before init arrives)
5. Add JSDoc explaining: this simulates the extension→webview direction only; the optional initPayload dispatches the view-init message after the ready signal

Key anti-patterns to avoid:
- Do NOT use sync `act()` — use `await act(async () => {...})` (sync act is deprecated in React 18)
- Do NOT import stores inside the reset function — they must be imported at module level for capture-at-import to work
